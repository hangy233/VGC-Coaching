# Champions M-C battle work

For team preview, live decisions, replay review, or an authorized M-C BO3 batch,
read `skills/champions-mc-matchups/SKILL.md` and its required cycle reference.
The repository skill folder is the maintained source. Before a new battle search,
use `battle_skill_status` (or `scripts/sync-skill.mjs --check`) and resolve a stale
installed copy. Prefer `battle_skill_sync` for reviewed installation, then
`battle_skill_read` to deliver the complete updated guidance and obtain the current
read receipt. Read the files into active context rather than relying on an old summary.

**Every BO3 must conclude with a private decision review and skill checkpoint
before the next authorized search.** Record a supported reusable change or an
explicit reason for no change, validate relevant scenarios, and sync changed
guidance. This also applies after wins, forfeits, a context handoff, and the final
set in a batch. Report `review complete / lesson or no change / sync verified`.
An idle server or unused battle allowance does not prove this review occurred.
See `skills/champions-mc-matchups/references/headless-battle-cycle.md` for the
checkpoint fields. Prefer `battle_review_save` and verify `battle_review_status`;
do not handwrite a completed status to bypass evidence checks. Run
`battle_preflight` before the next search. These tools validate stored evidence
and readiness; tactical judgment and this instruction are not a runtime review
guard in `battle_start`.

After each user-defined batch, follow the cycle's batch pattern review: find
recurring opposing cores and blocking mechanisms, develop checked answers, and
retain successful forcing sequences with applicability limits. Store the compact
synthesis in the final BO3's team-owned checkpoint. Before the next authorized
batch, read those plans; audit their actual application when opportunities recur.
A winning score or synchronized skill alone does not prove they were applied.

**Between batches, update shared guidance from supported transferable lessons.**
When an existing rule is repeatedly missed, improve its trigger, ordering or
compact decision check; citing "already covered" alone is insufficient. Keep
team-specific plans private. Validate the changed behavior and a counterexample,
sync the complete skill folder, and read the updated guidance before the next
authorized batch. Record changed source paths, the behavioral correction and
adoption in the final checkpoint. A genuine evidence-based no-change result is
valid when no supported improvement is available; explain that specifically
without inventing a lesson or duplicating a rule. Per-set no-change reviews do
not replace this batch-level shared-guidance checkpoint.

**After every batch, investigate and repair every observed control failure.**
Include failures inside wins and recovered turns. Follow the cycle's control
repair checkpoint: identify causes from actual traces, fix the relevant runtime
or operator workflow, validate the failure and a normal countercase, and record
each cause as repaired, mitigated or unresolved with evidence and adoption status.
Skill wording or a successful fallback alone is not a control repair. Unresolved
failures that can compromise control block the next batch until repaired or
covered by a validated mitigation. Preserve normal batch-end shutdown; verify
loaded runtime changes at the next normal authorized startup, without extra
battles or authentication merely to test them.

Close the battle client after each user-defined batch, unless the user gives a
newer keep-open instruction. Keep it open between BO3s within that batch. After
the final official result and server idle, finish replay preservation, metrics,
review/skill sync and bounded retention, then call `battle_stop` and verify
shutdown. Missing durable evidence or an incomplete review defers closure;
protected disposable files can remain explicitly retained. Start the next
already-authorized batch through the saved-login broker, carrying forward the
overall remaining battle allowance; stored credentials grant no extra battles.

Use open sheets and plausible opposing paired actions to choose a plan; use actual
MCP `calculate_damage` and `calculate_speed` for all numerical damage and Speed
checks. Do not use mental arithmetic or a direct calculator fallback. Label
unknown opposing investments and unsupported calculations explicitly.
Use optional `evidenceContext` to retain actual calculator inputs/results for
`battle_note_decision` and review references. Decision notes record agent claims;
they do not establish server acceptance, execution or the opponent's intent.

Protect the active turn deadline: submit complete legal paired choices promptly,
keep a compact handoff, and do long reviews only between BO3s. Separate selected,
accepted, executed, server-defaulted, and inactivity outcomes. A source update does
not update an already running client. Do not start battles, change the roster,
publish replays, authenticate again, or commit/push merely to validate a skill.
